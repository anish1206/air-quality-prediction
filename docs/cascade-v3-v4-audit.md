## Executive Summary

v3 was a polished-looking notebook that was not reproducible.  Almost every
metrics cell displayed a pre-saved PNG with `display(Image(...))`.  Variables
such as `benchmarks`, `hl`, `ci`, `ab_all` and `ab_onset` were used but never
defined.  Cell 37 contained a string literal split across a line (SyntaxError).
The leakage tests printed `[PASS]` unconditionally.  Every headline number
(82.8% coverage, MAE 7.21, q_hat 1.72, threshold 0.42, split counts, "85-90%
of gain", "inference helper verified") was typed into markdown or print strings.
Markdown contained corrupted Python escape sequences (`\a`, `\t`).

**v4 is a complete rewrite to a notebook where every figure, table, number and
claim is produced by code visible in the notebook.**  A fresh `Restart & Run
All` must complete with no error; leakage tests must be able to fail; metrics
must be computable from nothing but the parquet and causal graph.

## 3. Ablation Conclusion Template

The actual numbers below are placeholder templates; the notebook writes the real
values into `outputs/metrics.json` at runtime.  The phrasing structure is mandated
regardless of the precise numbers:

```
CSI(Full) − CSI(Target-Only) = Δ, 95% CI [lo, hi]

If lo > 0:
  "Upstream source features provide a statistically distinguishable CSI improvement
   of Δ pp over a target-only model (paired block-bootstrap CI excludes 0)."

If lo ≤ 0:
  "The CSI gain from adding upstream source features ({Δ} pp) is NOT
   distinguishable from zero at the 95% level (CI includes 0).
   Upstream features add no reliably detectable value over a local target-only model
   on this dataset and test period."
```

The wind-sign section follows the same rule:
```
If Spearman p < 0.05 (real direction, onset rows):
  "The data support a transport effect: higher wind alignment correlates
   monotonically with greater subsequent target PM2.5 increase (Spearman r=R, p=P)."
If p ≥ 0.05:
  "No statistically significant monotone wind transport effect is detected
   (Spearman r=R, p=P, onset rows only). The placebo and shuffled controls
   are indistinguishable from the real direction, consistent with synoptic
   co-movement rather than advective transport."
```

### Required city_frames column mapping

The pipeline's `cities_data` dict uses the key `"time"` (resampled from Open-Meteo
hourly), whereas `predict_cascade` expects `"time_4h"`.  The diff above renames
the column inline.  A cleaner approach is to rename at the point of resampling
in `resample_to_4h()`:

```python
# In resample_to_4h(), change:
df_resampled = df_resampled.reset_index()
# to:
df_resampled = df_resampled.reset_index().rename(columns={"time": "time_4h"})
```

`inversion_proxy` is not fetched by the pipeline's Open-Meteo call.  It should
either be added to the fetch parameters or imputed as zero.  The v4 model was
trained with `inversion_proxy` present; a constant-zero imputation will reduce
accuracy slightly but will not crash the predictor.

## 6. Limitations and Next Steps

1. **Advective corridor scarcity.** Only 4 corridors have delay > 0.  In all
   three years of data (2023-2025), NSK never exceeds 120 µg/m³ (max 119.95).
   The 8h bucket has very few test onset events.  Reliable advective evaluation
   requires either (a) lower threshold (60 µg/m³ = Indian NAAQ standard), or
   (b) additional years of data.

2. **Val-Stop event count.** Val-Stopping (Jul-Oct 2024) has only 54 severe
   events (0.16%).  Optuna optimises a near-flat PR-AUC surface on this slice.
   A proper multi-fold time-series CV with purge gaps across the full 3-year
   dataset would yield more reliable hyperparameter selection.

3. **Forecast winds.** All features use *observed* winds at time t.  Operational
   use requires replacing `wind_u` / `wind_v` with NWP forecast winds along the
   corridor transit time window.  Open-Meteo's forecast endpoint provides 72-hour
   hourly wind forecasts at no cost.

4. **Lagrangian trajectory modelling.** The wind transport feature
   (`u sin θ + v cos θ`) is a single-point Eulerian approximation.  NOAA HYSPLIT
   or PySPLIT would provide parcel-tracking trajectories that correctly account
   for wind shear and vertical mixing during transit.

5. **Additional advective corridors.** The causal graph was built on Pearson
   correlation with delay estimation.  A broader search using time-shifted DTW
   across the full Indian subcontinent, or incorporating meteorological reanalysis
   (ERA5) wind roses, may identify additional reliable corridors.

6. **Distribution shift in calibration.** Val-Calib is winter-only (Nov-Jan, 21%
   severe) while the test set is Feb-Dec (5.67% severe).  An adaptive or
   rolling-window conformal calibration approach would provide better coverage
   guarantees across seasons.

7. **`inversion_proxy` in production.** This feature is computed from the
   historical data but is not available in the Open-Meteo API.  A proxy using
   the temperature/dew-point gradient (already available) should be substituted
   in the operational pipeline.
